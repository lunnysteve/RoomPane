# Home Display review — 10 October 2026

Reviewed the current local Studio, designer, screen rotation, plugin engine, installation/update scripts, release workflow and Android TV source. Also checked the running Pi, which reports version 1.2.1.

Follow-up implementation: version 1.3.0 includes the fixes below, encrypted backup/restore, independent persistent screen sleep, connection messages, browser CI gates and updater-helper migrations with rollback. A fresh extracted release is now tested with a real dependency install. See INSTALL.md for backup limits and full Pi recovery. Physical Android TV and fresh SD-card installation remain hardware checks; performance changes and additional canvas presets remain future improvements. The review findings below record the original assessment.

## Bugs fixed

| Problem | Fix | Verification |
| --- | --- | --- |
| The rotator ignored Studio's manual screen-off state. | Apply the state when polling configuration; keep the overlay closed to tap-to-wake while manually off. | Browser verifies visible overlay after off/on API changes. |
| Page schedules stayed on the previous playlist when the hour/day changed. | Recheck eligibility every 15 seconds, rebuilding frames only when the eligible list changes. | Browser advances across an hour boundary with unchanged configuration and checks the actual frame content. |
| Equal sleep/wake times made the screen sleep all day. | Equal times now mean always on; Studio explains this. | Browser verifies always-on, overnight sleep and next-morning wake. |
| An incomplete external URL such as `http://` crashed Add page. | Validate the URL and show a readable error before changing the playlist. | Studio browser check confirms the form stays open, no page is added and no JavaScript error occurs. |
| Duplicate page IDs, unsafe URL schemes and malformed schedules could be saved through the API. | Reject these values before writing configuration. | Server tests cover duplicate IDs, malformed URLs, inline credentials and invalid schedule values. |
| Creating another screen whose name produced an existing address silently replaced its playlist. | Reject address collisions for new screens; editing an existing screen still uses its explicit ID. | Server test confirms the original playlist survives a colliding name. |

## Recommended next work

### Before public release

1. **Run browser checks in CI.** The release workflow currently runs Node and updater tests but not the browser suites. Add all four browser scripts, including `tests/display-browser.py`, to a check on pushes/pull requests and make release publication depend on it. The blank-screen and manual-sleep bugs demonstrate why API-only coverage is insufficient.
2. **Add backup and restore.** Provide a Studio export/import for pages, uploads, fonts, screen profiles, plugin definitions and connections. Credentials need explicit handling and protected backup storage. Document a full Pi backup separately; application rollback does not restore lost user data. README currently promises backup coverage in INSTALL.md, but that guide lacks a dedicated backup procedure.
3. **Show connection failures on displays.** Initial config/plugin fetch failures can leave an empty black viewport. Show a small connecting/retrying message when no page has loaded, while preserving the current page during temporary outages.
4. **Test the APK on real Android TV hardware.** Verify remote navigation, saved URLs, launch behavior, screensaver entry/exit, Wi-Fi loss/reconnection and upgrade over the previous signed APK. A successful APK build does not establish these behaviors.
5. **Verify a fresh Pi installation and an in-app upgrade to the next version.** Current checks cover the existing installation and mocked rollback. Include settings/media preservation. The web updater replaces the application directory but does not upgrade its root-owned helper or systemd unit; future helper changes need a defined migration path.

### Usability and performance

6. **Give each screen its own sleep controls and schedule.** Profiles currently choose playlists, while sleep is global. This is surprising when a wall display and living-room TV need different hours. Studio now explicitly labels the shared behavior.
7. **Reduce work in hidden pages.** Rotation creates every eligible iframe and reloads a page as it becomes active. This keeps hidden weather/plugin/video pages running and may show a loading flash. Consider keeping only the current and next page loaded, with an explicit lifecycle for plugin polling and media playback. Measure on the Pi before changing the rotation strategy.
8. **Add plugin management tools.** The shared manifest/SDK is a useful foundation. Next steps are definition uninstall, version/compatibility reporting, missing-renderer errors and checks before deleting files referenced by plugins. Keep the current explicit trust model for community HTML; a public catalogue would benefit from isolated previewing and a clearer trust notice.
9. **Extend the designer beyond its fixed 800 × 480 canvas.** Add portrait and 16:9 presets with a clear fit/fill choice so TV layouts can use the available area intentionally.

## Limits

This was a source review, automated browser/API testing and a short live-service check. It was not a physical Android TV test, a fresh SD-card install, a prolonged Pi load test or a penetration test. Real Google Calendar/Home Assistant accounts were not exercised; their protocol paths were tested against local fixtures.
